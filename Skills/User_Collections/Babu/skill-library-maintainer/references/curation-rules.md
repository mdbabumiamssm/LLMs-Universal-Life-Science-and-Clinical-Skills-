# Curation Rules

## Rewrite a skill when

- The frontmatter is invalid or noisy.
- The body is mostly examples instead of instructions.
- The trigger is too vague to invoke reliably.

## Split into references when

- The skill body is long because of tables, examples, or domain notes.
- Only part of the content is needed per task.
- You want to preserve detailed material without spending context by default.

## Add a new skill when

- The workflow is important and recurs.
- Existing skills force the wrong abstraction.
- The new skill has a clear trigger that is not already covered well.
